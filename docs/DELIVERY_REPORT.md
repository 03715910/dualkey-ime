# 開発結果：DualKey IME 0.1.0

2026-10-31時点の初期開発版です。設計だけではなく、Android Studioプロジェクトとインストール可能な署名APKを作成しました。Phase 1・2の実装とエミュレーター確認を進め、Phase 3は公開操作を残しています。すべての仕様が完成したという報告ではありません。

## 1. 実装済み

- InputMethodServiceとしての登録、日本語12キーフリック、独立した数字行、英語QWERTY、Shift/Caps Lock、削除・空白・Enter。
- 共通の入力処理を使う物理キー入力、ローマ字変換、候補操作、日本語・英語切り替え。
- 接続検出と通常・省スペース・完全非表示、手動優先と記憶、ショートカット、設定画面・タイルからの復帰経路。
- DataStore設定、簡易日本語・英語予測、簡易文章変換、ユーザー辞書。
- Google ML Kitの日英翻訳、方向選択、結果プレビューと確定、モデル取得・削除、パスワード欄の制限。
- 更新確認、WorkManager、任意の自動ダウンロード、公式配布先制限、実APKのハッシュ・暗号署名・証明書・アプリID・バージョン検証、標準インストーラーへの案内。
- 独立した配布サイトのHTML/CSS/JS、リリースAPKからメタデータと履歴を生成するスクリプト、明示的な公開用GitHub Actions。

## 2. 未完成・制限

Mozc本体は未導入です。現在の変換は小規模辞書と最長一致であり、一般的な日本語IMEと同等の辞書量・文節解析・長文精度はありません。翻訳結果の直接編集、任意の確定済み全文の翻訳、自由なショートカット割り当ては未実装です。物理配列はAndroid側の設定に従います。

リポジトリ作成、ソース公開、署名Secrets登録、正式なAPK/Pages公開、実配信のversion.json生成、GitHub Actionsの実行は、公開操作の確認待ちです。Samsung実機・実物のBluetooth/USBキーボードは未確認です。

## 4. Android Studioで開く

Android Studioを起動し「Open」→上の`DualKeyIME`フォルダーを選びます。Gradle同期を待ちます。端末へ実行する場合は「app」を選びます。SDK 35とJDK 21を使って確認しています。詳しい操作・コマンドはREADMEを参照してください。

## 5. ビルド結果

Debug、署名Release、Android Test APKの生成に成功。JVMテスト11件とWebテスト9件は成功。Android LintはDebug/Releaseともエラーなしです。新しい依存バージョンの案内、国際化などの警告は残っています。

## 6. APK

配布用のローカル成果物：`output/DualKeyIME-0.1.0.apk`（約67MB）。SHA-256は`output/SHA256SUMS.txt`にあります。アプリIDは`io.github.user03715910.dualkey`、versionCodeは1、Android 8.0以上です。今回専用のリリース鍵で署名し、v2/v3署名の検証に成功しています。

## 9. インストール

`output/DualKeyIME-0.1.0.apk`をスマートフォンへコピーして開きます。必要なら使用したファイルアプリやブラウザの「不明なアプリのインストール」を許可し、Android標準の画面でインストールしてください。

## 10. キーボードの有効化

DualKey IMEを開き「1. キーボードを有効にする」で有効化します。AndroidのIME警告を確認してください。続いて「2. 使用するキーボードを選択」でDualKeyを選び、メモアプリなどの入力欄をタップします。

## 11. 物理キーボード

Bluetoothのペアリング、またはUSB接続をAndroidで行います。日本語モードでKYO→きょ、KYOUHA→きょうは、Spaceで変換、矢印で選択、Enterで確定します。Escで変換を解除できます。半角/全角・英数・かな・Ctrl+Spaceで言語を切り替えます。OSが先にショートカットを処理する場合は画面の切り替えボタンを使います。

## 12. 表示切り替え

Ctrl+Alt+Kで通常表示と完全非表示を切り替えます。キーボードの「省スペース」「全表示」「隠す」も使えます。完全非表示で画面操作へ戻す場合は、ホーム画面からDualKeyを開き「画面キーボードを通常表示に戻す」を押してください。クイック設定へ「DualKeyを表示」タイルも追加できます。フォーカスがない別アプリの入力欄を強制表示せず、まずアプリのテスト欄を表示する設計です。

## 13. 更新方法

**現在のローカルAPKは配布先が未設定なので、実サーバーの自動更新は利用できません。** 公開設定を完了して再ビルドしたAPKを、一度手動で上書き導入する必要があります。署名鍵は維持するため、アンインストールは不要です。

公開設定後の運用では、アプリの「今すぐ更新を確認」→「更新APKをダウンロード」→「検証済みAPKをインストール」と進めます。自動ダウンロードを有効にすると、検出と取得をバックグラウンドで行います。

## 14. 自動化の範囲

起動時・約12時間ごと・手動で更新確認します。定期処理の時刻はAndroidが調整します。自動ダウンロード、Wi-Fi限定、通知を設定できます。インストールは利用者がボタンを押し、Androidの許可・確認を行う方式です。入力中にインストールを突然始めません。確認を回避する非公開API・root・アクセシビリティ操作は使っていません。
