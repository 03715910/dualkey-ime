### 不要なキーボード表示の確認

動画はテストAPK内の別プロセスで、端末上に生成したMP4を実際にループ再生しています。テスト用のActivity・操作Receiverは**配布APKには含めていません**。全画面・回転・PiPはAndroidの通常のAPIで実行し、IMEの表示だけでなく、入力先へ余分なIME領域が割り当てられていないことも確認しました。

| 依頼の操作 | 結果と範囲 |
| --- | --- |
| 縦動画、横画面、全画面、全画面解除 | 実施済み。非入力画面で表示されず、追加IME領域0 |
| 動画の小窓化・ホーム・アプリ切替 | 実施済み。PiP、Launcher、Android設定との切替で不要表示なし |
| 入力欄の表示要求 | 実施済み。検証用入力欄とアプリ内入力欄で正常に表示。LINE実機は未確認 |
| 入力中の縦横切替 | 実施済み。未確定ローマ字と変換状態を維持し、入力を継続。OSで隠した状態では回転しても復活せず、明示的な再表示後も重複なし |
| 手動表示・非表示 | 実施済み。通知・共通ショートカット・設定と、素早い同一キー切替。入力欄なしでの表示操作は次の実際の入力欄まで保留 |
| 実物Bluetooth／USBの接続・切断 | **未確認**。物理キーは注入したKeyEvent、接続ポリシーはCoreの状態テストであり、実物機器の試験ではない |

原因は、構成変更・入力機器の更新で`requestShowSelf()`を無条件に呼び、表示判定が入力先を確認せず通常表示の設定だけを見ていたことでした。構成変更ではOS標準の復元に任せ、入力終了・接続解除・OSによる非表示で保留表示を取り消します。手動表示の再試行は入力セッションへ限定し、直前の非表示アニメーションと競合する要求を重ねません。

途中では、回転でクライアントの接続が置換される間の空の読込や、まだコマンドを受け付けない接続により、ローマ字が欠けたり既存文字と重複したりする問題も検出しました。未確定文字列・入力欄・カーソルを照合し、接続が準備できてから公式の`setComposingRegion()`で所有範囲を復元するよう修正しています。確認できない範囲への書込みは行いません。初回のXMLコンストラクター不備、旧ボタン名・旧ScrollView前提のテスト、入力先の準備前の操作も修正しました。全画面のAndroid初回案内がフォーカスを持つ場合は、試験側で案内を閉じています。製品からシステム画面を自動操作するコードはありません。上記の最終結果は、修正後に再実行した結果です。

画像は`output/usability-0.1.11/visibility/`（全画面動画・PiP・横画面の入力）と`output/usability-0.1.11/continuous-candidates.png`です。
