# 0.1.8：確定後の続きの言葉

「続きを」を変換・確定し、未確定の下線が消えた後にも「お願いします」「教えてください」「見せてください」などを表示します。候補を選ぶと確定済みの文章を消さずに後ろへ追加します。追加した言葉からも次の提案へつながります。

## 操作

- 候補をタップすると確定した文字列として追加します。未確定の下線は付けません。
- 下矢印で候補を選び、Enterでも追加できます。選んでいないEnterは従来どおり改行・確定・送信です。Spaceは勝手に候補を採用せず、通常の空白になります。
- 完全非表示中の矢印キーは、見えない続きの候補を選ばず、従来のカーソル移動へ渡します。候補を操作する場合は通常表示・省スペース表示を使ってください。
- 文字を打ち始めると通常の入力中の候補へ戻ります。Escで確定後の候補を取り消せます。
- カーソル移動、範囲選択、確定済み文字の削除、空白・改行、入力モード・入力先の変更は前の文脈を取り消します。候補を押した瞬間にも、元の語句がカーソル直前にあり、位置と選択状態が一致することを確認します。
- 「設定 → 変換と辞書 → 日本語の予測候補」で、入力中と確定後の予測をまとめてON/OFFにします。

## 共通の候補と学習

依頼、挨拶、日時、よく使う助詞など、端末内の共通フレーズから提案します。これは任意の文章を理解する大規模言語モデルではありません。共通フレーズにない語句は、学習済みのつながりがあれば提案します。すべての単語から提案するものではありません。

学習ONの場合、続けて確定した2つの語句を1つの組合せとして保存します。回数が多い組合せを上位にし、同じ回数なら最近の使用を優先します。候補タップだけでなく、次の語句を自分で入力・確定した場合も学習します。入力先・カーソル位置をまたいで関連付けません。

組合せは端末内のSQLiteに最大5,000件、従来の変換学習は別の表に最大5,000件を保持します。`dualkey_learning.db`のバージョン1から2では新しい表を追加し、従来の変換回数や表記を削除しません。「学習データを削除」は両方の表を同じトランザクションで削除し、削除前に待機していた保存操作による復活も防ぎます。手動のユーザー辞書には影響しません。

## プライバシーと安全性

- 入力文をネットワークへ送りません。共通フレーズと端末内の使用回数だけを利用します。
- パスワード、数値、メール・URL、予測禁止の欄では確定後の提案をしません。
- 学習OFF・`IME_FLAG_NO_PERSONALIZED_LEARNING`がある欄では、個人の組合せを保存・参照しません。共通フレーズだけを使います。
- 保存対象は80文字までの短い語句で、数字、メールアドレス・URL・制御文字を含む前の語句は組合せの対象から外します。入力の全履歴やキー操作を記録する方式ではありません。
- Googleによる表記切り替えの翻訳結果は組合せの文脈にしません。
- Androidの編集APIから位置や直前の文字を確認できない場合は、その候補を追加しません。通常の文字入力は継続します。

周辺文字の照合にはAndroidの[InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection)を使い、現在のIMEが管理している直前の確定語句と未確定部分だけを照合します。
