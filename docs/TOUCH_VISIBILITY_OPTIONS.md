# スマホからの表示／非表示：次の実装候補

0.1.9では物理キーの表示／非表示ショートカットを設定できるようにし、スマホ側の新しい常設ボタンは追加していません。以下は検討案です。

| 方法 | 使い方と表示 | 制約・現状 |
| --- | --- | --- |
| クイック設定タイル（第一候補） | 上から通知パネルを下ろし、1個のタイルで表示／非表示を切り替える。入力中は何も常設しない | 既存の「DualKeyを表示」タイルはアプリを開いて表示する片方向の復帰用。両方向の操作は今後の変更。入力欄のフォーカス・OSの制限を受けるので、元のアプリで即時復帰できる経路を実機で確認する必要がある |
| 通知のボタン | 「表示／非表示」の操作を通知内へ配置。入力画面にはボタンを置かない | 利用者が任意に有効化。Android 13以降は通知の許可が必要。パネルを開く操作が増える。フォーカスが失われた場合の復帰も設計が必要 |
| 省スペースの操作欄 | 外付けキーボード接続中に候補欄と小さな「全表示」ボタンだけを残す | 現在の省スペース表示がこの方法に近い。タップしやすいが、小さい画面領域は常に使う。完全非表示からは別の復帰方法が必要 |

入力欄のダブルタップは、その欄を所有するアプリのジェスチャーです。通常のIMEが他のアプリの欄を共通して監視するためのタッチ用コールバックはなく、単語の範囲選択とも重なります。各アプリの協力なしに全入力欄へ実装する方式は採用しません。画面上へ透明の入力領域を重ねる方式も、入力先のタップを妨げるため候補に含めていません。

画面を広く使いたい希望には、クイック設定の1個のタイルが最も合うと判断します。実装する場合は、表示／非表示でタイルの状態を変え、入力フォーカスがない場合だけ復帰用の案内を出す設計を検討します。現行タイルが元の入力欄へ直接キーボードを出せると報告していません。

参考：[Androidのクイック設定タイル](https://developer.android.com/develop/ui/views/quicksettings-tiles)、[TileService](https://developer.android.com/reference/android/service/quicksettings/TileService)、[ビューに対するジェスチャー検出](https://developer.android.com/develop/ui/views/touch-and-input/gestures/detector)。
