# 0.1.5：候補の拡充、フリックの吹き出し、変換学習

## 漢字と候補数

従来のMozc公開辞書へ、同じ固定リビジョンの単漢字・異体字データと、[Unicode Unihan 17.0.0](https://www.unicode.org/Public/17.0.0/ucd/)の`kJapanese`を追加しました。異体字には元の字の読みも補います。一般的な「𠮷」の「よし」という読みも補っています。

| 項目 | 0.1.5 |
| --- | ---: |
| 読み | 746,734 |
| 読みと表記の組 | 1,197,477 |
| 品詞違いを含む項目 | 1,397,157 |
| 単漢字・異体字として持つ字種 | 51,669 |
| 新たに追加した読みと表記の組 | 112,185 |
| 圧縮辞書 | 24,158,267バイト |
| 展開辞書 | 75,135,116バイト |

字形を表示できるかは、端末のフォントにも依存します。一般的な辞書語に加えて古字・異体字も含み、すべてが日常の日本語で使われる字という意味ではありません。元のUnicodeライセンスをAPKへ同梱し、アプリのライセンス画面にも追加しました。

候補は標準100件・最大1,000件まで検索できます。以前から明示設定されている候補数は維持します。「一覧」では最初の50件を表示し、「次の50件を表示」で追加します。まだ検索件数が少ない場合は「さらに候補を検索」から100件ずつ増やせます。

候補数に応じて文の探索幅を1,000へ増やすことはせず、文のつながりを判断する探索と、単語・単漢字の追加検索を分けました。候補帯には選択中の周囲12件を表示して描画量を抑えます。読みの登録数によって実際の候補件数は異なります。

## フリックの吹き出し

かなキーを押すと、キーの上へ丸みのあるひし形と吹き出しの先端を表示します。中央・左・上・右・下の文字を5つのセルに分け、指の方向へ選択色を移します。例えば「か」では中央が「か」、左が「き」、上が「く」、右が「け」、下が「こ」です。

Android ViewsのCanvasで独自に描画し、PopupWindowで指の上へ表示します。タッチを奪わず、指を離す・キャンセル・キーを取り外す際に消します。パスワード欄ではプレビューを表示しません。他社のアイコン・画像は使っていません。

## 変換学習

初期状態は日本語の学習ONです。「設定」→「変換と辞書」から停止・削除できます。

- 対象はIMEが管理し、利用者が選択・確定した日本語の語句です。候補タップ、変換中のEnter、次の入力による変換確定などを記録します。
- 保存するのは読み、表記、使用回数、最終使用時刻です。キー操作の履歴、クリップボードの監視、外部アプリの全文収集は行いません。
- 同じ読みの候補では使用回数を優先し、回数が同じなら最終使用時刻で並べます。入力途中の読みが学習済み語句の先頭に一致すれば、予測にも表示します。
- 予測を選んだ場合は、入力途中の読みではなく補完後の読みを保存します。「いいかん」から「いい感じ」を選ぶと「いいかんじ」として覚えます。
- パスワード・数値・URL・メール入力欄、予測禁止の欄、および[IME_FLAG_NO_PERSONALIZED_LEARNING](https://developer.android.com/reference/android/view/inputmethod/EditorInfo#IME_FLAG_NO_PERSONALIZED_LEARNING)を指定した欄では、学習データの保存と順位への利用を無効にします。
- 未確定入力のキャンセル、フォーカス移動による未確定入力の終了、翻訳結果、英語入力は今回の日本語学習の対象外です。

データはアプリ専用のSQLiteデータベース`dualkey_learning.db`へ保存し、通信に含めません。バックアップ・端末間転送の対象からも除外します。同じ署名とアプリIDで上書き更新した場合は維持します。最大5,000組を頻度と最終使用時刻で保持し、使用回数は上限1,000,000としています。

学習OFFでは既存データを順位に使わず、追加保存を止めます。削除操作は学習だけを消し、手動で登録したユーザー辞書を残します。削除前に保存待ちだった操作でデータが復活しないよう、保存世代をチェックしています。

変換の順位は読みごとの確定回数で調整します。文章全体の意味を個人向けの言語モデルとして再学習する機能ではありません。実施した試験と実機未確認の範囲は[テスト結果](TEST_RESULTS.md)に記録します。
