# 0.1.4：日本語辞書と変換処理

以下は0.1.4時点の設計です。現在の字種・候補数・学習機能は[0.1.5の変更](LEARNING_AND_FLICK.md)を参照してください。

従来の約100語の辞書では、文章を最長一致で切り、各単語の最初の表記だけを使っていました。例えば「いいかんじ」の「感じ」という別候補を文章へ組み合わせられませんでした。

0.1.4では、APKへ辞書を同梱して端末内で読み込みます。初回の辞書準備に通信は不要です。入力内容の送信・ログ保存・自動学習は追加していません。

## データ

出典は[google/mozc](https://github.com/google/mozc/tree/e5f1494923a0a624d01f19c50d57bbdfa03ea5ba/src/data/dictionary_oss)の固定リビジョン `e5f1494923a0a624d01f19c50d57bbdfa03ea5ba` です。dictionary00～09、品詞ID、品詞の接続コスト、除外規則を使用します。

生成結果は `app/src/main/assets/japanese/manifest.json` に記録します。

| 項目 | 値 |
| --- | ---: |
| 読み | 745,963 |
| 読みと表記の組 | 1,085,292 |
| 品詞の違いを含む項目 | 1,284,972 |
| 品詞の接続コスト | 2,672 × 2,672 |
| APK同梱の圧縮辞書 | 23,428,846バイト |
| 端末内で展開する辞書 | 73,598,370バイト |

項目数は「重複しない日本語の単語数」ではありません。固有名詞、活用形、表記違いを含みます。[Mozc辞書の説明とライセンス](https://github.com/google/mozc/blob/e5f1494923a0a624d01f19c50d57bbdfa03ea5ba/src/data/dictionary_oss/README.txt)の通り、Google日本語入力の非公開辞書とは異なります。

元のBSD・IPAdic/ICOT・沖縄辞書の通知をAPKとリポジトリに同梱し、アプリの「アプリについて」→「ライセンス・利用技術」から全文を読めます。

## 処理

- 読み索引と予測用の範囲最小値索引により、毎回すべての語を走査せずに検索します。
- 各位置の単語候補、語のコスト、前後の品詞接続コストを使って、複数の文章候補を残します。「いい感じ」「良い感じ」「いい漢字」などを同時に選べます。
- 文末の未完部分にも前方一致を適用し、「いいかん→いい感じ」「きょうはにほ→今日は日本語」などを予測します。
- ユーザー辞書は優先し、文の途中でも組み合わせます。ひらがな・カタカナや未知文字の原文も残します。
- 辞書の展開とハッシュ確認、通常の予測検索は入力/UIスレッドの外で行います。古い入力の予測結果は採用しません。Spaceでの変換はEnterとの順序を維持します。
- 入力欄を消した直後に新しい入力を始める場合、遅れて届いた選択通知で新しい未確定入力を解除しないよう、現在のカーソル位置と照合します。API31以降は[SurroundingText](https://developer.android.com/reference/android/view/inputmethod/SurroundingText)、それ以前は[ExtractedText](https://developer.android.com/reference/android/view/inputmethod/ExtractedText)で位置だけを判断し、内容は保存・送信しません。
- 候補数の標準は30件、設定範囲は2～60件です。既存の明示設定は変更しません。候補欄の「一覧」は文字キーの領域を置き換え、キーボードを縦へ増やさずに選べます。
- 初回の準備中や容量不足時も文字入力を継続し、準備状況を候補欄・辞書設定に表示します。展開ファイルはバックアップ対象外です。

## 再生成

Python 3.11以降で、プロジェクト直下から実行します。

```powershell
python tools/build_japanese_dictionary.py
```

固定リビジョンの原本を `.local/mozc-source` に取得し、索引・辞書・マニフェストを生成します。生成物を同梱するため、通常のAndroidビルドと利用者の初回起動ではGitHubへの辞書取得が不要です。原本ごとのSHA-256もマニフェストに記録します。

## 範囲と検証

これはMozcの**公開データを使う独自のKotlin変換処理**です。Mozcのネイティブエンジン、予測モデル、各種リライター、学習処理を丸ごと移植したものではありません。[公式Android手順](https://github.com/google/mozc/blob/e5f1494923a0a624d01f19c50d57bbdfa03ea5ba/docs/build_mozc_for_android.md)の別ツールチェーン/JNI構成を導入せず、既存の変換インターフェースを交換しました。

候補は件数と探索幅を制限します。161文字以上の一括入力は原文・カタカナを優先し、分けて変換してください。全Unicode漢字、すべての同音異義語、長文・固有名詞での完全な精度を保証するものではありません。英語予測の辞書は今回の変更対象外です。

実施結果・実機未確認の区別は[テスト結果](TEST_RESULTS.md)へ記録します。
